1. DESCRIPCION GENERAL
------------------------------

UBBike es una aplicacion movil multiplataforma destinada a gestionar el ingreso, permanencia y retiro de bicicletas en los bicicleteros de la Universidad del Bio-Bio.

Actualmente el proceso es manual, con registro en papel por parte del guardia. El sistema propuesto digitaliza este proceso utilizando codigos QR, permitiendo mayor seguridad, trazabilidad y eficiencia.

---

2. OBJETIVO DEL SISTEMA
------------------------------

Desarrollar un sistema compuesto por una aplicacion movil y un backend que permita:

- Registrar usuarios, estudiantes y funcionarios.
- Registrar bicicletas.
- Generar codigos QR para ingreso y salida.
- Validar acceso mediante guardia.
- Registrar movimientos de ingreso y salida.
- Mantener historial completo.
- Registrar incidencias.
- Identificar en cual bicicletero ocurre cada movimiento.
- Asignar guardias a los bicicleteros.
- Notificar a central cuando un usuario requiere presencia o servicio del guardia.

---

3. ARQUITECTURA GENERAL
------------------------------

El sistema sigue una arquitectura cliente-servidor:

- Cliente: aplicacion movil Flutter.
- Servidor: API REST en Node.js, Express y TypeScript.
- Base de datos: PostgreSQL.

La logica de negocio vive en el backend para centralizar reglas, trazabilidad y seguridad.

7. MODELO DE DATOS RELACIONAL
------------------------------

USUARIO:
- id.
- nombre.
- correo.
- rol: ESTUDIANTE, FUNCIONARIO, GUARDIA, ADMIN_CENTRAL o ADMINISTRADOR.
- contrasena_hash.

BICICLETERO:
- id.
- nombre.
- ubicacion.
- activo.

Regla del proyecto:
- La universidad cuenta actualmente con dos bicicleteros.
- Se modelan en base de datos para mantener trazabilidad y permitir cambios futuros sin modificar codigo.

BICICLETA:
- id.
- usuario_id.
- descripcion.
- foto_url.

ASIGNACION_GUARDIA:
- id.
- guardia_id.
- bicicletero_id.
- inicia_en.
- termina_en.
- activa.

SOLICITUD_GUARDIA:
- id.
- solicitada_por_usuario_id.
- bicicletero_id.
- guardia_asignado_id.
- tipo: GUARDIA_AUSENTE o REQUIERE_SERVICIO.
- estado: PENDIENTE, VISTA, EN_CAMINO, RESUELTA o CANCELADA.
- mensaje.
- creada_en.
- resuelta_en.

MOVIMIENTO:
- id.
- bicicleta_id.
- usuario_id.
- bicicletero_id.
- tipo: INGRESO o SALIDA.
- validado_por_guardia_id.
- creado_en.

INCIDENCIA:
- id.
- usuario_id.
- bicicletero_id.
- bicicleta_id.
- descripcion.
- estado.
- creada_en.

Relaciones principales:
- Un usuario puede tener muchas bicicletas.
- Una bicicleta pertenece a un usuario.
- Un bicicletero puede tener muchos movimientos, solicitudes e incidencias.
- Un guardia puede tener asignaciones a bicicleteros.
- Una solicitud de guardia siempre pertenece a un bicicletero.
- Un movimiento siempre debe registrar el bicicletero y el guardia que valido el acceso.
